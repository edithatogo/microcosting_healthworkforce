## Execution boundaries and dependencies

The current planning lane owns only this track directory. The existing PSA owner
retains source/tests, pyproject.toml, uv.lock, tooling/stubs, private evidence and
canonical conductor/ records in the integration worktree. This plan assigns no
portion of that active scope to a second writer. Registration is an integrator
operation after review, not a competing setup in the older migration checkout.

Phase 0 requires a terminal handoff containing exact source commits, changed paths,
qualified runtime/lock identity, commands/results, evidence locations retained by
the owner, unresolved scientific questions, and explicit remaining ownership.
A clean checkout, an idle chat, an old receipt or a green test is not a handoff.
Rebase the task inventory on that packet: mark inherited work as completed only
with attributable evidence, and remove duplicated implementation from this plan.
Do not restart the PSA owner's experiments or copy private native bindings.

After the handoff, the integrator assigns a separate implementation worktree and
scoped paths before any source writes. Dependency/CI promotion, shared registry,
main and remote metadata remain with the integrator. Use ordinary hooks; stage
only the reviewed owned paths. The source-only packet excludes private evidence.

Dependencies:

- Phase 1 follows Phase 0 ownership/baseline reconciliation. Formula/identity
  assurance may proceed while scientific questions remain unresolved; productivity
  domain changes wait for a model-owner unit/compatibility decision.
- Phase 2 follows Phase 1 configuration contracts and the PSA terminal handoff.
  Consolidation can establish compatibility parity without claiming scientific
  acceptance. No distribution reinterpretation, clipping or weighting change is
  inferred from numerical agreement.
- Phase 3 follows stable Phase 2 common-draw parity and source provenance.
- Phase 4 follows Phase 1 table contracts and a frozen input/reference baseline;
  it can be sequenced independently of Phase 3 by the integrator.
- Phase 5 follows the receiving-source handoff; reconcile each item against work
  already completed. It need not wait for scientific PSA acceptance.
- Phase 6 optional adoption requires a recorded need, qualification and scoped
  implementation authority. An explicit reasoned defer outcome completes an
  evaluation; installing or implementing every candidate is not required.

Scientific uncertainty blocks dependent scientific changes and final scientific
acceptance, not unrelated documentation or technical assurance. Record a bounded
technical completion with open scientific blockers rather than closing the
existing migration track prematurely.

## Verification and deliverables

Use the explicitly selected repo-local Python 3.15.2 interpreter and verify its
actual version. Adopt a later patch only through the existing integrator's
qualified runtime promotion. Behavioural changes begin with focused failing
regressions; documentation-only edits use content/link/build checks. Keep pytest
cacheprovider enabled, zero retries and exact affected selectors; failure-only
reruns use --lf --last-failed-no-failures=none. An empty selection is no evidence.
Do not change global addopts to implement selection.

At each phase checkpoint record source/lock identity, changed paths, focused
selectors and terminal results, manual output inspection where relevant, reused
evidence and why it remains valid, blockers and the next owner. Apply the
canonical workflow's verification protocol. Use full local gates at coherent
milestones without repeating unchanged expensive oracle runs. The designated
owner supplies workbook acceptance; no second writer repeats native operations.

Performance adoption requires a repeatable practical improvement on a stated
representative workload with acceptable memory and unchanged results; establish
that threshold before running the trial. No fixed speedup is promised. Select
scientific tolerances from the accepted baseline; do not loosen them to pass.
Clean wheel/sdist checks must inspect contents/licences and execute outside the
source checkout using supported explicit input/config paths.

Acceptance evidence stays in its existing private location. Track documents keep
only safe summaries and source references. No new skills are required from the
installed Conductor catalog for this Python/Polars scope.
